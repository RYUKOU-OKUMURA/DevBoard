 # TODO 機能改修の理想プラン

本ドキュメントでは、特定リポジトリの Issue・Pull Request に対する TODO 管理を強化し、
AI エージェント（Codex/Claude Code）との連携を洗練させるための実装計画と UI/UX アイデアをまとめる。

## 1. プロダクトゴール
- **Issue への TODO 書き込み**: ローカルまたはアプリ内から TODO を起票し、指定した GitHub Issue に自動反映。
- **メンション呼び出し**: Issue/PR コメントで `@Codex` や `@ClaudeCode` をメンションすると、該当スレッドで応答する。
- **リポジトリ横断 TODO 管理**: リポジトリ単位でタスクを整理し、進行状況や担当を可視化。

## 2. アーキテクチャの理想形
1. **フロントエンド (Vite/React/Tailwind)**
   - リポジトリ選択、Issue/PR 検索、TODO ボード表示を提供。
   - Webhook/イベントログ表示と、メンション結果のスレッドビュー。
2. **バックエンド (Cloudflare Workers / Functions)**
   - GitHub App/Token での Issue/PR API 連携。
   - TODO 同期サービス: ローカル DB (KV/SQLite) と GitHub を双方向同期。
   - メンションエージェントハンドラー: コメントを受信し、LLM 呼び出し、返信投稿。
3. **ジョブランナー / キュー**
   - 送信失敗のリトライ、バッチ同期、メンションリクエストの並列処理。
4. **ストレージ**
   - TODO メタデータ: status, assignee, repo, issue/PR link, tags, due。
   - 監査ログ: GitHub 側への投稿履歴、エージェント応答ログ。

## 3. 機能要件
- **TODO 起票/編集**
  - UI から TODO を作成し、対象リポジトリ・Issue を指定。
  - オフライン/ドラフト保存 → 後続同期キューで GitHub Issue コメントとして投稿。
  - TODO の状態遷移 (open/in-progress/done) を UI と GitHub 上のチェックボックスに反映。
- **メンション呼び出し**
  - Issue/PR コメントで `@Codex`/`@ClaudeCode` を検知し、アプリの webhook が受信。
  - 受信後、LLM 推論を実行し、返信を同スレッドに投稿。
  - コマンド式トリガー例: `/assign @user`, `/plan`, `/todo add <text>`。
- **リポジトリ別 TODO ボード**
  - カンバン/リスト表示。ラベル・担当・期限でフィルタ。
  - GitHub でのステータスと同期し、複数リポジトリを横断集計。
- **権限と監査**
  - GitHub App の権限スコープを最小化 (issues:write, pull_requests:write, contents:read)。
  - 監査用に、誰がいつどの TODO をどこに反映したかを記録。

## 4. UI/UX アイデア
- **統合 TODO パネル**: 画面左でリポジトリ/ブランチ選択、右でタスク詳細。Issue/PR へのリンクとメンション履歴を同時表示。
- **インライン編集 & 同期状態表示**: TODO ごとに「同期待ち/成功/エラー」をバッジ表示。再送ボタンを配置。
- **メンションスレッドビュー**: 対象 Issue/PR のコメントを時系列で表示し、エージェントの応答を強調。再実行ボタンを提供。
- **クイックアクション**: タスクカード上で `/plan`, `/todo add`, `/assign` などのメンションテンプレをワンクリック挿入。
- **フィルタ & 集計**: リポジトリ別、担当別、ステータス別の集計カード。今週期限のタスクをハイライト。
- **通知 UX**: 同期失敗やメンション返信完了をトースト通知。Slack/メール連携オプション。

## 5. 実装ステップ案
1. **GitHub 連携基盤**
   - GitHub App 認証、Webhook 受信エンドポイントを実装。
   - Issue/PR コメント投稿と検索 API の薄いクライアントを用意。
2. **TODO モデル & 同期キュー**
   - TODO エンティティ: `id, repo, issueNumber, title, body, status, tags, assignee, due, syncState`。
   - 送信キュー (retry/backoff) と受信キューを実装し、冪等キーで二重送信防止。
3. **メンションハンドラー**
   - `/plan`, `/todo add`, `/assign` などのコマンドを正規化し、LLM と GitHub API を組み合わせて応答。
   - 安全ガード: 実行前に内容をサニタイズし、危険な操作を抑止。
4. **UI 開発**
   - TODO ボード + 詳細サイドパネル + スレッドビュー。
   - 同期状態と再送操作を持つタスクカード。
5. **観測性/監査**
   - すべての同期・メンション操作をイベントログに保存。UI で絞り込み表示。
6. **リリース & 権限確認**
   - スコープ確認、テナントごとの GitHub App インストールフローを整備。

## 6. メトリクス
- TODO の GitHub 反映成功率 / 平均遅延
- メンション応答成功率 / 平均応答時間
- 同期エラー再送率
- ユーザごとの完了タスク数、期限超過率

## 7. リスクと緩和
- **GitHub レートリミット**: キューでスロットリング、ETag/If-None-Match を活用。
- **エージェント暴走/誤投稿**: コマンドホワイトリストとスレッド限定返信で被害を局所化。
- **権限過剰**: read-only を基本とし、書込は Issue/PR コメントのみに限定。
- **データ不整合**: 冪等キーとイベントソーシングで再処理を容易に。

## 8. 次のアクション (短期)
- GitHub App/トークン連携の PoC を作成し、Webhook 受信 → コメント返信までの Happy Path を動かす。
- TODO モデルと同期キューのスケッチをプロトタイプ実装し、UI に同期状態バッジを表示。
- `/plan` `/todo add` `/assign` の 3 コマンドをメンション経由で動かす MVP を構築。
