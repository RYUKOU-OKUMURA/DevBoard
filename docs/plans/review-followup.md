# DevBoard 改善計画（レビュー結果対応）

対象バージョン: 現行 main / 2025-10  
目的: 直近のコードレビューで判明したリスク（認証まわりの欠陥とデータ分離の不足）を優先的に解消し、機能要件の抜けを埋める。

## 優先度一覧
- **P0 (直ちに対応)**: CORS/CSRF の穴塞ぎ、GitHub プロキシの権限制御
- **P1**: キャッシュ/手動リポジトリのアカウント分離
- **P2**: 表示要件の微修正、回帰防止テストの追加

## 作業計画

### 1. 認証・CORS・CSRF の締め付け (P0)
- 現状: `ALLOWED_ORIGINS` 未設定時に全 Origin を許可し、`Access-Control-Allow-Credentials: true` を返しているため、クロスサイトからセッション付きリクエストが成立する。
- ゴール/完了条件:
  - `ALLOWED_ORIGINS` 未設定時はデフォルト拒否（または明示的なアプリ Origin のみ許可）にし、許可リスト外は 403。
  - `Access-Control-Allow-Credentials` を許可 Origin のみに限定。
  - `/api/*` の書き込み系 (POST/PUT/PATCH/DELETE) に Origin チェックまたは CSRF トークン（同一オリジンのみなら Origin チェックで十分）を追加。
  - 追加の自動テストでヘッダー検証を通過。
- タスク:
  1) middleware の Origin 判定を厳格化（デフォルト deny / ワイルドカードの明示使用のみ）。  
  2) `requiresAuth` パスでの Origin 不一致は即 403。  
  3) 書き込みメソッドに CSRF/Origin ガードを追加。  
  4) miniflare などで CORS/CSRF のユニットテストを作成。  

### 2. GitHub プロキシの権限制御 (P0)
- 現状: 任意パス・メソッド・ボディを GitHub API に転送し、GraphQL もフリー入力。CORS 許可と組み合わせて Issue 変更などができる。
- ゴール/完了条件:
  - プロキシで許可するパス/メソッドのホワイトリストを定義（例: `/github/graphql/repos/*` は read-only クエリのみ、mutation 禁止。REST も GET だけ許可）。
  - GraphQL のクエリ名/文をサーバ側で固定化（プリセットクエリをサーバで持ち、クライアントは名前だけ指定）。
  - 不許可なリクエストは 403/405 で即遮断し、レスポンスに詳細を含めない。
  - ログにトレーサブルな拒否理由を残す（PII 非含有）。
  - ユニットテストで mutation/未知パスが拒否されることを検証。
- タスク:
  1) REST/GraphQL の許可リスト設計と実装。  
  2) クエリ ID 制＋サーバ側テンプレート化の実装。  
  3) 不許可時のレスポンス/ログ方針策定。  
  4) テスト追加。  

### 3. リポジトリキャッシュと手動追加リポジトリのアカウント分離 (P1)
- 現状: localStorage のキーがグローバルで、マルチアカウント間でデータが混在。
- ゴール/完了条件:
  - viewer/custom キャッシュキーを `devboard_viewer_repos:<accountId>` などに変更し、旧キーからのマイグレーションを実施。
  - 手動追加リポジトリも同様に `manual-repos:<accountId>` で分離。
  - アカウント切替時にキャッシュを読み間違えないことを手動/自動テストで確認。
- タスク:
  1) すべてのストレージキーを accountId 付きに変更し、migrate フラグで一度だけ移行。  
  2) `useRepositories`/`useManualRepositories` で accountId 必須化。  
  3) マイグレーション後に旧キーをクリーンアップ。  
  4) テスト追加。  

### 4. UI 表示要件の修正 (P2)
- 現状: リポジトリ名が `repo / owner` の順で表示されている。
- ゴール/完了条件: 仕様通り `owner/name` で表示。関連スナップショット/ユニットテストを更新。
- タスク: `RepoCard` 表示の順序修正＋テスト。  

### 5. テストとリリース手順 (横断)
- CORS/CSRF/プロキシのガードをユニットテスト（Miniflare/Pages Functions）に追加。
- マルチアカウント切替のキャッシュ誤用を再現する回帰テストを追加。
- リリース前チェックリストに「ALLOWED_ORIGINS 設定確認」「プロキシ許可リスト確認」を追記。

## ロールアウト方針
- P0 を最優先で短期リリース（機能フリーズも可）。  
- P1 は P0 マージ後に短いフィーチャーブランチで対応。  
- P2 は次リリースでまとめて対応。  
- すべての変更で e2e smoke（ログイン→リポジトリ表示→手動追加→TODO 表示）を確認すること。
